# Рулетка: план реализации

Спецификация: `docs/superpowers/specs/2026-10-07-roulette-design.md`. Ветка `roulette` (в ней же правка «результат блэкджека — 3 секунды»).

Каждый шаг: сначала падающие тесты, потом код, потом `npm test` и `npm run typecheck`, потом коммит. К следующему шагу — только когда текущий зелёный.

## Решения сверх спецификации

- У снимка стола появляется поле `kind: GameId` на верхнем уровне: TypeScript сужает тип по нему, а по вложенному `table.game` — нет. Остальная форма снимка блэкджека не меняется.
- Правило «выигрывает ли поле при числе» и множитель выплаты лежат в `shared`: сервер по ним считает, клиент по ним подсвечивает выигравшие поля.
- Правило «сидеть можно только за одним столом» остаётся в общем слое `rooms.ts`, потому что касается нескольких столов сразу; рулетки оно не касается.
- Отсчёт ставок рулетки — своя константа `ROULETTE_BET_MS = 25_000`; вращение — `SPIN_MS = 5_000`; результат — общая `RESULT_MS`.

## Интерфейсы

`shared/src/index.ts`:

```ts
export type GameId = 'blackjack' | 'roulette';
export type RouletteField = `n${number}` | 'red' | 'black' | 'even' | 'odd' | 'low' | 'high'
  | 'dozen1' | 'dozen2' | 'dozen3' | 'col1' | 'col2' | 'col3';
export const ROULETTE_FIELDS: readonly RouletteField[];   // все 49 полей
export const WHEEL_ORDER: readonly number[];              // 37 чисел в порядке европейского колеса
export const RED_NUMBERS: ReadonlySet<number>;
export const roulettePayout: (field: RouletteField) => 35 | 2 | 1;
export const rouletteWins: (field: RouletteField, number: number) => boolean;
export type RoulettePhase = 'waiting' | 'betting' | 'spinning' | 'result';
export interface RoulettePlayerView {
  player: PlayerInfo; connected: boolean;
  bets: Partial<Record<RouletteField, number>>; ready: boolean; net: number | null;
}
export interface RouletteView {
  phase: RoulettePhase; players: RoulettePlayerView[];
  timeLeftMs: number | null; number: number | null; history: number[];
}
export type TableSnapshot =
  | { kind: 'blackjack'; table: TableInfo; seats: (SeatView | null)[]; spectators: number; game: BjView }
  | { kind: 'roulette'; table: TableInfo; game: RouletteView };
export interface RouletteDetails { number: number; bets: Partial<Record<RouletteField, number>> }
export interface RouletteStats { rounds: number; wagered: number; net: number; biggestWin: number; numberHits: number }
// События клиента: 'roulette:bet'(field, amount, ack), 'roulette:clear'(ack), 'roulette:ready'(ack)
```

## Шаги

### 1. Перенос блэкджека под ведущего стола

- `server/src/rooms/host.ts`, `server/src/rooms/blackjack-table.ts` (места, пропуски, таймеры — из `rooms.ts`), `server/src/rooms.ts` (присутствие, выбор ведущего по `table.game`, `freeBalance` по всем столам через `stakeOf`, учёт «сидит за одним столом»).
- `shared`: `GameId`, `kind` в снимке; `RoomDeps.settle` получает игру стола; `realtime.ts` передаёт её в `settleRound`.
- Тесты: существующие 160 проходят; правки в них — только добавление `kind: 'blackjack'` там, где снимок сравнивается целиком.

### 2. Правила рулетки

- `shared`: поля, порядок колеса, красные числа, `roulettePayout`, `rouletteWins`, константы времени.
- `server/src/games/roulette.ts`, `server/test/games/roulette.test.ts`.
- Тесты: выплата по каждому виду поля (число, цвет, чёт/нечет, половины, дюжины, колонки); зеро — выигрывает только `n0`; ставки на одно поле складываются; отказы: поле не из списка, сумма меньше 5, дробная, сверх 5 000 в сумме, сверх свободного баланса, ставка и сброс после «Готов», «Готов» без ставок, любые действия во время вращения и результата; сброс последним игроком возвращает в ожидание; чистый результат при нескольких ставках, часть которых выиграла; цвета вдоль `WHEEL_ORDER` чередуются, в `WHEEL_ORDER` ровно 37 разных чисел.

### 3. Ведущий стола рулетки

- `server/src/rooms/roulette-table.ts`, `server/test/rooms-roulette.test.ts`; `Rooms` получает методы `rouletteBet`, `rouletteClear`, `rouletteReady` и зависимость `spinNumber: () => number`.
- Тесты: первая ставка запускает 25 секунд; сброс всех ставок отменяет отсчёт; досрочный старт, когда «Готов» у всех присутствующих поставивших; зритель без ставки старт не держит; старт по таймеру играет ставки без «Готов»; число в снимке с начала вращения, а расчёт и сообщение о балансе — через 5 секунд; результат 3 секунды, потом очистка; история — пять последних, новые первыми; ушедший после ставки остаётся в игроках с `connected: false`, досрочный старт его не ждёт, после раунда исчезает; сбой расчёта аннулирует раунд без показа результата; фишки на кону в рулетке недоступны за столом блэкджека и наоборот; действие рулетки за столом блэкджека и действие блэкджека за столом рулетки получают отказ; пустой стол удаляется, и история с ним.

### 4. Сокеты, столы и HTTP

- `realtime.ts`: события `roulette:*` с проверкой входа; реакции в рулетке — любому присутствующему. `tables.ts`: `createTable(db, creator, appLink, game)`, `listVisitedTables(…, game)`; название стола — «Рулетка игрока …» для рулетки. `app.ts`: `POST /api/tables { game }`, `GET /api/tables?game=`; игра не из списка — 400; без `game` — блэкджек, чтобы уже открытые клиенты не сломались при выкладке.
- Тесты: раунд рулетки двумя игроками через сокеты, фишки сошлись с журналом; мусор в событиях рулетки не роняет сервер; создание и список столов по играм; реакция от присутствующего в рулетке принимается.

### 5. Статистика

- `stats.ts`: `getRouletteStats`; `PlayerStats` получает блок `roulette`; `getBlackjackStats` по-прежнему считает только раунды блэкджека.
- Тесты: счётчики по нескольким раундам, включая попадание в число и раунд в ноль; раунды рулетки не попадают в статистику блэкджека; рейтинг учитывает обе игры.

### 6. Клиент: выбор игры и общая рамка стола

- `Lobby.tsx` (рулетка активна, игра передаётся дальше), `App.tsx` (экран столов знает игру), `Tables.tsx`, `api.ts`.
- `Table.tsx` — рамка: подключение, служебные экраны, шапка, чат; `BlackjackTable.tsx` — нынешнее содержимое стола; `realtime.ts` — действия рулетки в `useTable`.
- Проверка: блэкджек в браузере работает как раньше (сесть, поставить, сыграть раздачу, чат, реакция).

### 7. Клиент: экран рулетки

- `RouletteTable.tsx`, `roulette.css`: полоса игроков, поле 3×12 с зеро, колонками, дюжинами и ставками на группы, свои фишки на полях, панель (номинал, сумма, свободный баланс, отсчёт, «Сбросить», «Готов»), подсветка выигравших полей.
- Порядок игроков: отправивший реакцию — первым, пока не отправит другой.
- Проверка в браузере двумя игроками: ставки, сброс, «Готов» у обоих — досрочный старт; один не нажал — старт по таймеру; отказ при превышении баланса; ширина телефона 360 px без горизонтальной прокрутки страницы.

### 8. Колесо, анимация и история

- `components/Wheel.tsx`: SVG из 37 секторов по `WHEEL_ORDER`, указатель сверху; во вращении — несколько оборотов с замедлением до выпавшего сектора за остаток `timeLeftMs`; в результате — число крупно. Ряд истории из пяти чисел с цветом.
- Проверка в браузере: колесо останавливается на числе из снимка (сверить с числом в панели и с начислением); зашедший посреди вращения видит остановку на том же числе; история сдвигается.

### 9. Завершение

- `CLAUDE.md`: раздел «Устройство» — ведущие столов и рулетка; `.env.example` не меняется.
- Полный прогон: тесты, типы, сборка клиента.
- Независимое ревью ветки, исправление находок.
- Выкладка в `main` — после подтверждения владельца.
