# Казино с друзьями в Telegram: первая версия (блэкджек)

Дата: 2026-10-07. Исходная постановка — `PROMPT.md`. Факты о платформе — `CLAUDE.md`.

## 1. Цель и границы

Telegram Mini App, в который компания друзей заходит по ссылке из группового чата и играет в блэкджек на виртуальные фишки за общим столом в реальном времени.

В объёме: лобби, баланс и касса, блэкджек, реакции, чат стола, рейтинг и статистика, деплой и минимальный CI/CD.

Вне объёма: покер и рулетка, реальные деньги и платежи, проработка дизайна, анимации, звук, кастомные эмодзи Telegram, хранение истории чата, удаление и настройка столов, локализация (интерфейс только на русском).

Требование к расширяемости: вторая игра подключается без переписывания кошелька, стола, чата, реакций, лобби и рейтинга.

## 2. Принятые решения

### 2.1. Вход за стол

- Игрок создаёт стол в лобби. У стола есть постоянный случайный код.
- Ссылка-приглашение: `https://t.me/<бот>/<приложение>?startapp=t_<код>`. Приложение читает код из `start_param` и сразу открывает этот стол.
- Кнопка «Пригласить» за столом: копирует ссылку и открывает диалог Telegram «Поделиться» (`https://t.me/share/url?url=…` через `openTelegramLink`).
- В лобби есть список «Мои столы»: столы, которые игрок создал или посещал (последние 10). Нужен, чтобы вернуться за стол при запуске не по ссылке.
- Стол существует бессрочно. Если за ним никого нет, раздачи не идут.
- Игрок может сидеть только за одним столом одновременно.
- Открыть стол можно не садясь (зритель). Зритель видит игру, чат и реакции и может писать в чат; реакции доступны только сидящим.

### 2.2. Правила блэкджека

- 6 колод в башмаке (312 карт). Перетасовка между раздачами, когда в башмаке осталось меньше 78 карт. Тасование — Фишер–Йетс на криптографическом генераторе.
- Дилер останавливается на любых 17, включая мягкие.
- Блэкджек (туз и десятиочковая карта с первых двух карт, не после сплита) оплачивается 3:2. Половина фишки округляется в пользу игрока: выигрыш = ⌈ставка × 1,5⌉.
- Если открытая карта дилера — туз или десятиочковая, дилер проверяет закрытую. При блэкджеке дилера раздача заканчивается сразу: блэкджек игрока — ничья, остальные руки проигрывают.
- Удвоение: на любых первых двух картах руки, в том числе после сплита. Ставка руки удваивается, игрок получает ровно одну карту.
- Сплит: один раз (максимум две руки), для двух карт одинакового достоинства по очкам (10 и король — можно). На разделённые тузы выдаётся по одной карте, ход по ним не делается. 21 после сплита — не блэкджек, выплата 1:1.
- Страховки и сдачи нет.
- Ничья: ставка возвращается.
- Если все руки игроков перебрали или получили блэкджек, дилер открывает закрытую карту, но не добирает.
- Удвоение и сплит доступны, только если свободного баланса хватает на вторую ставку.

### 2.3. Стол и таймеры

- 6 мест.
- Подсесть можно в любой момент; ставка — со следующей раздачи.
- Фазы раздачи: ожидание → ставки → раздача → ходы игроков по порядку мест → ход дилера → расчёт → показ результата 3 секунды → ожидание.
- Ставки: фаза начинается с первой подтверждённой ставки и длится 20 секунд либо заканчивается раньше, когда поставили все сидящие. Подтверждённую ставку изменить нельзя. Не поставил — пропускает раздачу, оставаясь за столом.
- Ход: 30 секунд на каждое решение. По истечении — автоматический stand.
- Два пропуска подряд (не поставил или не походил вовремя) — игрок автоматически встаёт из-за стола.
- Игрок нажал «Встать» посреди раздачи: его оставшиеся руки сразу получают stand, результат засчитывается, место освобождается после расчёта.
- Потеря связи: рука доигрывается по таймерам, результат засчитывается. Вернувшийся игрок получает актуальный снимок стола.
- Второе подключение того же игрока (другое устройство) вытесняет первое.
- После расчёта, если баланс игрока меньше минимальной ставки, он автоматически встаёт из-за стола и видит предложение пойти в кассу.

### 2.4. Ставки

- Минимум 5, максимум 5000, одинаково для всех столов.
- Ставка набирается тапами по фишкам номиналов 1, 5, 25, 100, 500, 1000 и подтверждается кнопкой.
- Свободный баланс = баланс − фишки, стоящие на кону в текущей раздаче. Ставка, удвоение и сплит ограничены свободным балансом.

### 2.5. Баланс и касса

- Один баланс на все игры.
- При первом входе игрок получает 1000 фишек. Это не считается походом в кассу.
- Касса доступна всегда. Быстрые суммы: 1000, 5000, 25 000, 100 000, плюс поле для своей суммы. Одна выдача — от 1 до 100 000 фишек. Число выдач не ограничено.

### 2.6. Реакции

- Тап по своей аватарке за столом открывает выбор из восьми эмодзи: 😂 😡 🎉 😭 😎 🤔 👍 🤡.
- Реакция показывается у аватарки игрока всем за столом 3 секунды. Новая реакция того же игрока заменяет предыдущую.
- Формат сообщения: `{ kind: 'emoji', value: '😂' }`. Поле `kind` оставляет место для кастомных эмодзи Telegram (второй вид с идентификатором и раздачей файла через наш сервер).

### 2.7. Чат стола

- Текстовые сообщения до 200 символов, видны всем подключённым к столу.
- Сервер сообщения не хранит. Клиент держит их в памяти, пока открыт экран стола.

### 2.8. Рейтинг и статистика

Единица учёта — раздача игрока (сплит — одна раздача с двумя руками). Итог раздачи — её чистый результат в фишках: больше нуля — победа, меньше — поражение, ноль — ничья.

Рейтинг (общий для всех пользователей, сортировка по чистому результату):
- выиграно — сумма чистых результатов выигранных раздач;
- проиграно — сумма модулей чистых результатов проигранных раздач;
- чистый результат — выиграно минус проиграно.

Фишки из кассы и стартовые фишки в рейтинг не входят.

Статистика игрока по блэкджеку:
- выиграно, проиграно, чистый результат;
- сыграно раздач; победы, поражения, ничьи; процент побед (победы / раздачи);
- число блэкджеков;
- процент переборов — доля раздач, в которых перебрала хотя бы одна рука;
- самый крупный выигрыш за раздачу (максимальный чистый результат);
- самая крупная ставка — максимальная сумма, поставленная в одной раздаче, с учётом удвоений и сплита;
- самая длинная серия побед и самая длинная серия поражений (ничья серию не прерывает и не продлевает);
- число удвоений и доля удвоенных рук, закончившихся выигрышем;
- число походов в кассу и сумма взятых там фишек.

### 2.9. Визуал

- Вертикальная ориентация, приложение открывается на полную высоту.
- Лобби, касса, рейтинг и статистика — компоненты `@telegram-apps/telegram-ui`, цвета из темы Telegram.
- Стол — обычная вёрстка на HTML/CSS: дилер сверху, шесть мест дугой, панель действий внизу. Карты и фишки — простые фигуры с текстом.
- Аватар — `photo_url`; если его нет или он не загрузился — кружок с инициалами.
- Анимации только там, где иначе непонятно, что произошло (появление карты, чей ход, результат руки).

## 3. Архитектура

Один Node-процесс на одном VPS: раздаёт собранный клиент, обслуживает HTTP API и соединения Socket.IO, хранит данные в файле SQLite. Перед ним Caddy, который выпускает сертификат и проксирует запросы.

Репозиторий — один, три пакета (npm workspaces):
- `shared` — типы сообщений и состояния, константы (лимиты, таймеры, номиналы, набор реакций);
- `server` — сервер;
- `client` — React-приложение.

### 3.1. Модули сервера

| Модуль | Что делает | От чего зависит |
| --- | --- | --- |
| `auth` | Проверяет `initData` (`@tma.js/init-data-node`, срок годности 24 часа), создаёт или обновляет игрока | База |
| `wallet` | Единственный, кто меняет баланс: стартовая выдача, касса, результат раздачи. Каждая операция — запись в журнале | База |
| `tables` | Создание стола, поиск по коду, список «Мои столы» | База |
| `table-room` | Живой стол в памяти: места, присутствие, чат, реакции, пропуски, рассылка снимков. Об игре знает только через интерфейс `Game` | `wallet`, `Game` |
| `games/blackjack` | Правила блэкджека как чистая машина состояний: башмак, фазы, ходы, расчёт | Ничего (генератор случайных чисел передаётся снаружи) |
| `stats` | Рейтинг и статистика запросами к итогам раздач и журналу | База |

Интерфейс `Game` (то, что реализует каждая игра):
- принять действие игрока и вернуть новое состояние;
- сообщить, чьего действия игра ждёт и какой сейчас таймер;
- обработать истечение таймера;
- выдать публичный снимок состояния (без скрытой информации);
- по завершении раунда вернуть итоги по каждому игроку: поставлено, чистый результат, детали для статистики игры.

`table-room` по итогам раунда вызывает `wallet` одной транзакцией: изменение балансов, запись в журнал, запись итогов раздачи.

### 3.2. Данные (SQLite)

- `users` — Telegram id, имя, username, `photo_url`, баланс, дата создания.
- `tables` — id, код, игра, название, создатель, дата создания.
- `table_visits` — стол, игрок, время последнего посещения.
- `rounds` — id, стол, игра, время завершения.
- `round_results` — раунд, игрок, поставлено, чистый результат, итог, детали игры в JSON (для блэкджека: блэкджек, был ли перебор, число удвоений, число выигравших удвоений).
- `ledger` — игрок, вид операции (`start`, `cashier`, `round`), игра, сумма, раунд, время.

Статистика и рейтинг считаются запросами по `round_results` и `ledger` при обращении, без отдельных счётчиков. Серии побед и поражений считаются проходом по раздачам игрока.

Только в памяти: текущая раздача, башмак, чат, реакции, присутствие. При перезапуске сервера незавершённая раздача аннулируется: баланс в базе не менялся, никто ничего не теряет.

Резервная копия: ежедневная копия файла базы на том же сервере, хранится 7 дней.

### 3.3. Протокол

Авторизация одинаковая для HTTP и Socket.IO: сырая строка `initData` (заголовок `Authorization: tma <initData>` и поле `auth` при подключении сокета).

HTTP API:
- `GET /api/me` — профиль и баланс (создаёт игрока при первом входе);
- `POST /api/cashier` — выдать фишки;
- `GET /api/rating` — рейтинг;
- `GET /api/stats/:userId` — статистика игрока;
- `POST /api/tables` — создать стол; `GET /api/tables` — «Мои столы»; `GET /api/tables/:code` — стол по коду.

Socket.IO (комната = стол):
- клиент → сервер: войти в комнату стола, сесть на место, встать, действие игры (ставка, hit, stand, double, split), сообщение чата, реакция;
- сервер → клиент: полный снимок стола при каждом изменении; отдельные события для сообщения чата, реакции и изменения баланса игрока.

Снимок одинаков для всех подключённых и не содержит закрытую карту дилера и содержимое башмака. Клиент не вычисляет состояние игры, а отображает последний снимок; после переподключения получает его заново.

### 3.4. Клиент

Экраны: лобби, касса, рейтинг, статистика игрока, стол. Список игр в лобби задаётся данными: блэкджек активен, покер и рулетка показаны как недоступные.

Связь с Telegram — `@tma.js/sdk-react`: `initData`, `start_param`, кнопка «Назад», тема, открытие ссылок.

React зафиксирован на версии 18 из-за `@telegram-apps/telegram-ui` (последний релиз 2.1.13 от октября 2025, peer-зависимость `react ^18.2.0`). Библиотека используется только на экранах лобби, кассы, рейтинга и статистики.

## 4. Ошибки и крайние случаи

- `initData` отсутствует или не прошла проверку: экран «Откройте приложение из Telegram».
- Стол с кодом из ссылки не найден: сообщение и переход в лобби.
- Все места заняты: игрок остаётся зрителем.
- Игрок уже сидит за другим столом: предложение пересесть (встаёт там, садится здесь; если там идёт его раздача — по правилу «Встать» посреди раздачи).
- Сервер отклонил действие (не твой ход, не хватает баланса, ставка вне лимитов): действие игнорируется, клиент показывает актуальный снимок.
- Потеря соединения: плашка «Переподключение…», Socket.IO переподключается сам.

## 5. Тестирование

- Правила блэкджека — модульные тесты на заранее заданном башмаке: выплаты, блэкджек, сплит, удвоение, проверка закрытой карты, округление 3:2, истечение таймеров.
- `wallet` и `stats` — тесты на SQLite в памяти.
- `table-room` — тесты с поддельными таймерами: пропуски, выход посреди раздачи, переподключение.
- Тестовый раннер — Vitest.
- Ручная проверка мультиплеера: режим разработки, в котором проверка `initData` заменена выбором поддельного игрока параметром адреса; несколько вкладок браузера — несколько игроков. Режим включается только переменной окружения и недоступен в проде.

## 6. Деплой

- Российский VPS (1 ядро, 1 ГБ памяти), домен, Docker Compose: контейнер приложения и Caddy. Файл базы — на томе.
- Настройки через переменные окружения: токен бота, ссылка на приложение (`t.me/<бот>/<приложение>`), домен.
- GitHub Actions: на каждый push — тесты и проверка типов; на push в `main` — сборка образа, публикация в GitHub Container Registry, выкладка на сервер по SSH.
- Регистрация в @BotFather: `/newbot`, затем `/newapp` с адресом нашего домена.
- Сервер к Telegram Bot API в первой версии не обращается.

## 7. Известные риски

- Telegram в России замедляется с февраля 2026 года. Сервер размещается в России и не зависит от доступности Bot API; аватарки с серверов Telegram могут не загружаться.
- `@telegram-apps/telegram-ui` не обновлялась год. Зависимость ограничена четырьмя простыми экранами.
